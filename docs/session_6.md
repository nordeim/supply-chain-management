Root cause: setSessionCookie marked the session cookie Secure whenever NODE_ENV=production, and CI (like any TLS-terminated deployment) serves the production build over plain HTTP. Chromium trusts loopback and accepts Secure cookies over HTTP — WebKit drops Secure cookies on any non-HTTPS transport, so the cookie never landed, router.refresh() re-rendered with no session, and the Sign Out button never appeared. One failing cookie-dependent test while every render/navigation test passed is exactly that signature.
Fix (commit d4ddd28): secure: await isHttpsRequest() — true only when the request arrived over TLS (x-forwarded-proto, first proxy-chain entry), false for direct plain-HTTP. Strictly more correct for real deployments too: a Secure cookie on a plain-HTTP transport is a bug (browsers drop it), not a hardening. Annotations now carry the first ~4 lines of each failure (locator + call-log detail), not just the first line.
